# Audit packet

The material for KeepCrypt-Entropy's independent security audit, the one docs/build-plan.md requires
before 1.0 ("Before 1.0"), prepared in M7 (tasks/todo.md, items G1 and G2; Q102). The owner chooses and
engages the auditor; this file gives them the scope, how to build and reproduce what they review, a
threat-model review against docs/design.md, the findings it made, every residual risk and
trust-on-first-use item recorded so far, and the questions we want answered.

0.1.0 is a pre-release, not for real funds until the audit's fixes are published (SECURITY.md).

## Scope (Q102)

| Area | Paths | Why |
| --- | --- | --- |
| Core | `core/` | All randomness, the pool, health and known-answer tests, seed, seal, go-ahead check, backup, export, braille |
| FFI | `ffi/` (`ffi/guard`, `ffi/jni`, `ffi/capi`) | The one call each app makes into core; the workspace's only unsafe code |
| Offline verifier | `tools/verify/verify.py` | What users trust to check a device without trusting it |
| Pi image | `pi/app/`, `pi/os/` | The firmware and the Buildroot image, its kernel config, its build container |
| Android | `mobile/android/`: capture protection (`secure-ui`), the ceremony, backup and document code | Screens that show secrets; files written and read |
| iPhone | `mobile/ios/`: capture-state redaction, the ceremony, backup and document code | The same, on iOS |

Out of scope for this audit: the seal registry server (`registry/`, M9), which no 0.1.0 artifact
trusts (release builds pin no registry key; see question 13).

## Building and reproducing what you review

- Every command, with what it checks: `CLAUDE.md`, "Commands"; CI: `.github/workflows/`.
- The Pi image, in the pinned build container: docs/pi-firmware.md, "Build, flash and verify".

- Why each rule exists: docs/design.md; every decision and its proof, milestone by milestone:

## Threat-model review (M7 G1, 2026-11-22)

Each attacker row of docs/design.md's threat model, and each core principle, against the code as it
stands: what answers it, the tests that prove it, what is left, and findings. Paths are relative to
`Entropy/` unless they start with `.github/`. `DS` = docs/design.md, `BP` = docs/build-plan.md, `PF` =
docs/pi-firmware.md, `MA` = docs/mobile-apps.md, `swb` = docs/seal-watchonly-braille.md. `todo:N` is
tasks/todo.md line N when this review was made (branch m7-hardening at d0fd4a16; later edits move them).
Findings are marked **new** (not recorded before) or **known** (recorded or scheduled, listed because a
doc still promises it). "To check" items are open questions, not findings.

### 1. Offline brute-forcer (DS:60)

Defense promised: at least 128 bits (prefer 256) of real min-entropy reaching a wide cryptographic pool.

#### What answers it
- Device leg D: a 512-bit SHA-512 pool, tag `KCE/v1/pool` first, records `id u16 BE || len u64 BE || data`,
  D = first 32 bytes of the digest (core/src/pool.rs:19, :32-58).
- The only OS read: `getrandom::fill` (core/src/source/os.rs:15-22); every error is `Source(Os)`.
  64 OS bytes absorbed last at commit (core/src/source.rs:30; core/src/session/inner.rs:175-179).
- Credit policy: Pi needs 512 credited hwrng bits at 4 bits/byte, phone 256 bits by policy for the OS read,
  dice-only 0 (core/src/source.rs:32-37, :86-117). Credit only through `CreditedSamples`, built only by the
  health tester, only for completed post-startup windows (core/src/health.rs:36-48).
- `commit` refuses with `QuotaUnmet` before reading the OS (core/src/session/inner.rs:169-171).
- Dice leg: faces 1-6 only, minimum 50 rolls (12 words), 99 (24 words), 99 after a collision
  (core/src/dice.rs:17-24, :44-61, :89); `finish` refuses below the minimum (inner.rs:215-217).
- E = SHA256("KCE/v1/seed" || D || len(R) u64 BE || R) or SHA256(R) in dice-only mode (core/src/seed.rs:6, :76).
- Shells pick the platform that sets the quota: Pi `Platform::Pi` (pi/app/src/app.rs:397), phones
  `Platform::Phone` (ffi/src/ceremony.rs:335).

#### Tests that prove it
- Pool vectors and framing: `every_keepcrypt_json_pool_case` (core/src/pool.rs:99);
  `every_bit_of_the_os_record_reaches_d` (core/src/pool.rs:149).
- No narrowing D -> C/E -> words: `every_bit_of_d_reaches_c_and_e` (core/src/seed.rs:666),
  `every_bit_of_e_reaches_the_words` (core/src/seed.rs:692), `the_length_of_r_is_hashed` (core/src/seed.rs:494).
- Credit policy: `credit_policy_table` (core/src/source.rs:251); `the_pi_quota_needs_a_whole_window_of_hwrng`
  (core/tests/error_injection.rs:394); `finish_below_the_minimum` (core/tests/error_injection.rs:521).
- Real OS source: `os_source_writes_every_byte_position` (core/src/source.rs:302),
  `two_real_sessions_give_different_commitments` (core/tests/os_source.rs:9).
- Birthday: `one_million_real_device_legs_never_repeat` (core/tests/birthday.rs:104) and the canary
  `narrowed_states_are_caught` (core/tests/birthday.rs:206), run nightly by `.github/workflows/entropy-nightly.yml`
  jobs "birthday (1,000,000 real device legs)" (:46) and "birthday canary (24- and 28-bit states)" (:72).
- Dice math vs Coldcard: `rolls_json_through_dice_only_sessions` (core/tests/vectors.rs:86),
  `dice_only_matches_coldcard` (core/src/seed.rs:513); verifier agreement in CI job "test" (entropy-ci.yml:162).

#### What is left
- The hwrng's 4 bits/byte and H = 4 are placeholders until lab data (core/src/source.rs:31; DS:190); no
  `ea_non_iid`/`ea_restart` data yet (DS:283; M8).
- The phone's device leg is the OS CSPRNG credited 256 bits by policy with no health test (DS:190).
- The birthday job exercises phone sessions (`Platform::Phone`, core/tests/birthday.rs:63) on the x86_64 CI
  runner only: not the Pi's hwrng path, not the armv6 or Android binaries, and no reboots (BP:320 defers them to M8).
- Dice quality is not checked: a user who types a pattern still meets the roll count (core/src/dice.rs:44-61;
  DS:90 names "user skipping rolls"). In dice-only mode that is the whole seed.
- 12-word seeds carry 128 bits by construction (first 128 bits of E), whatever the legs hold.

#### Findings
- (known, low) DS:198 and DS:278 describe the birthday test as "across process restarts and reboots" and a CI
  gate where "any collision fails the build"; it is a nightly, non-required workflow with no reboots
  (entropy-nightly.yml:46; BP:320). Stage H2 (todo:20876) owes the edit.
- (known, low) DS:167 asks for each credit to be "store[d] as a constant with the test data that justifies it";
  `HWRNG_BITS_PER_BYTE = 4` has no test data (core/src/source.rs:31-32). Scheduled for M8.

### 2. Malicious firmware or supply chain (DS:61)

Defense promised: user-verifiable dice mode, reproducible builds, signed releases, anti-exfil signing.

#### What answers it
- Commit-then-combine: C = SHA256("KCE/v1/commit" || D) shown before dice (core/src/seed.rs:68;
  pi/app/src/screens.rs:638-645); D revealed on request after the read-back (core/src/session.rs:464;
  pi/app/src/app/ready.rs:139).
- Offline verifier: tools/verify/verify.py (`commitment` :512, `mixed_entropy` :517, `dice_only_entropy` :523,
  seal :415-436); Python 3.9 job "verifier (python 3.9)" (entropy-ci.yml:437); release copy byte-equal to the tag
  and its selftest (entropy-release.yml:80, :84-95).
- One RNG path, no fallback: `getrandom_backend="linux_getrandom"` for Pi and Android
  (pi/os/package/keepcrypt-pi/keepcrypt-pi.mk:45; scripts/android-rust.sh:431; entropy-ci.yml:701-705).
- Artifact scan (`banned-api-check.sh --artifact`): test markers (scripts/banned-api-check.sh:95), RNG symbols
  and getrandom fallback modules (:108-117), required OS import (:128); run on release artifacts in job
  "cross" (entropy-ci.yml:780-815).
- Source gates: banned crates (deny.toml:58-65), `cargo deny/audit/vet` and `check-path-deps.sh` in job
  "supply-chain" (entropy-ci.yml:280, :309-312); `canaries.sh` proves the gates fire (:321); grep gate on
  sources, workflows and OS config (entropy-ci.yml:364-366).
- Fail-closed lint wall: core/clippy.toml:11-32; core/Cargo.toml:113-140 (`unsafe_code`, `unused_must_use`,
  `let_underscore_must_use`, `print_*` forbidden).
- Kernel: only the BCM2835 hwrng driver may be built (pi/os/expected/kconfig-required:7; every other
  `HW_RANDOM_*` in pi/os/expected/kconfig-forbidden:60-80).
- Reproducible Pi image: legs a and b compared on every run, and a third, emulated on an arm64 host, on the
  weekly schedule, release tags and dispatches (.github/workflows/entropy-pi-image.yml:117-123, 393); each
  leg's image scanned against pi/os/expected (:307-321).

#### Tests that prove it
- `a_fixed_stub_gives_the_vectors_d_and_c`, `one_changed_byte_of_any_source_changes_d`,
  `a_changed_source_id_or_a_dropped_extra_changes_d` (core/tests/source_substitution.rs:151, :237, :281).
- Typestate order: `compile_fail` (core/tests/typestate.rs:34) over core/tests/compile_fail/*.rs
  (e.g. `dice_before_commit.rs`, `words_before_finish.rs`, `no_skip_after_check_started.rs`).
- Gate self-tests: `banned-api-check.sh --selftest` shards (entropy-ci.yml:397-401), `--selftest-apk` (:367).

#### What is left
- **Signed releases do not exist yet**: no public key is committed (`Entropy/release/` absent), while PF:181
  already shows `minisign -Vm SHA256SUMS -p keepcrypt.pub`. Stage B4 / Q100 pending.
- Android APK reproducibility is not yet proven (Stage D1 unticked, todo:20830); iOS is not reproducible by design
  (BP:343).
- The Pi boots closed GPU firmware with no secure boot; the boot-screen hash is computed by the image it
  describes, so it "catches corruption, not a deliberately altered image" (PF:58; pi/app/src/device/rootfs.rs:19).
  dm-verity deferred (Q107, todo:20629).
- Verification protects generation only if the user runs it; a user who skips verify.py trusts the firmware
  (swb:177 row "Dishonest firmware hides seed data in the seal code").
- Anti-exfil signing is not applicable: KeepCrypt signs no transactions.
- Library code in the APK is not judged by the dex scan (Q59 (b)). With R8 shrinking (M7 D2b), Kotlin's `Random`
  is still reachable: androidx.activity's `ActivityResultRegistry` draws request codes from `Random.Default` for
  the camera prompt and the document pickers, and Kotlin's `PlatformImplementations` names it. No request code is
  a secret or reaches the pool; the app's own classes are scanned and clean.
- Supply-chain trust on first use: the 61 PGP signer keys pinned for Android artifacts (M5-12, todo:10818-10820)
  and later signers (todo:15164, :15535, :16585-16586, :16614-16615); Buildroot inputs hash-checked, not
  source-reviewed (todo:1065-1066, :9521).
- BP:283 requires two approvals for `core/`, `ffi/`, `pi/os/`; the ruleset requires none while there is one
  maintainer (.github/CODEOWNERS:7-10; todo:23621-23622).
- Release builds pin no registry key until M9 (core/src/seal/registry_key.rs:4-5), so the collision check in a
  `0.1.0` build accepts only a typed go-ahead code, which proves the checker saw T and n, not that it is honest
  (swb:142).

#### Findings
- (new, medium) Exfiltration channels other than signatures are not in the threat model. DS:61 names only
  anti-exfil signing for "leak the seed later" and DS:252 frames leakage as signature nonces, but the device
  writes device-chosen random bytes in plaintext to places that leave it: each age backup's 16-byte salt, 16-byte
  payload nonce and 4-byte file name (core/src/backup.rs:41, :273-276; core/src/backup/age.rs:72-73), and the
  8-byte check nonce n carried in the check QR's URL (core/src/seal/check.rs:37; swb:126, :132). Nothing a user
  or verify.py can check constrains these bytes, so malicious firmware could carry a 12-word seed's 128 bits in one
  backup's salt, a file the phone apps allow saving to a cloud folder (MA:158). Suggest: name
  the channel in DS's table and the audit packet, and state the user-side mitigation (treat the backup file as
  sensitive; prefer verified builds).
- (known, low) "Signed releases" (DS:61, BP:346) has no key or signature path in the repo yet (no
  `Entropy/release/keepcrypt.pub`; PF:181 cites it). Stage B4 / Q100.
- (known, low) BP:350's pre-1.0 audit scope omits `tools/verify`, while Q102's answer (todo:20607-20609, :20638)
  and DS:294 ("a full verification run") include it; recorded at todo:4765-4766 but BP not yet edited.

### 3. Local observer (DS:62)

Defense promised: private setup, no network radios, screen hygiene.

#### What answers it
- Pi, no radios: Pi Zero v1.3 hardware; `CONFIG_NET`, `CONFIG_USB_GADGET`, `CONFIG_SOUND`, `CONFIG_MEDIA_SUPPORT`,
  `CONFIG_HID` forbidden (pi/os/expected/kconfig-forbidden:2-3, :23-24, :27); audio off, UART off
  (pi/os/board/pizero/config.txt:9-10).
- Pi screen hygiene: privacy gate before any Protected screen (pi/app/src/screens.rs:305-307); 30 s cover,
  9 min warning, 10 min wipe (pi/app/src/input.rs:22-26); dice screen shows only the current pick, the count and
  bits ("Earlier rolls are never shown", pi/app/src/screens.rs:650-663).
- Android: `FLAG_SECURE`, hidden overlays, no recents screenshot (mobile/android/secure-ui/.../SecureActivity.kt:46-48),
  recording callback (:75); no network permission, no backup (mobile/android/app/src/main/AndroidManifest.xml:28-37);
  gate rules KtWindow and KtManifest (scripts/banned-api-check.sh:763, :862).
- iPhone: capture redaction and screenshot discard (mobile/ios/KeepCrypt/CaptureShield.swift:5, :59, :175);
  networking banned except the offline probe (scripts/banned-api-check.sh:968-975; mobile/ios/KeepCrypt/OfflineCheck.swift:11-15).
- Pool-derived values never shown by games: `game_random` (core/src/source.rs:182-184).

#### Tests that prove it
- Android: `everyScreenIsDrawnAndThenBlackInEveryCapture` (mobile/android/app/src/androidTest/kotlin/com/keepcrypt/entropy/CaptureTest.kt:585),
  `theRecentsThumbnailIsThePlaceholder` (:1089), `contentCaptureHasNothingOfTheApp` (:1373); job
  "android emulators" (.github/workflows/entropy-android.yml:653).
- iPhone: `testTheCaptureCoverReplacesTheSceneWhileCaptured`, `testThePrivacyCoverReplacesTheSceneWhileInactive`,
  `testAScreenshotDiscardsTheSessionAndSaysWhy` (mobile/ios/KeepCryptUITests/CaptureUITests.swift:18, :30, :44);
  `testStartOnlyOfflineAndGoingOnlineBringsGoOfflineBack` (OfflineUITests.swift:16).
- `game_random_writes_every_byte_position` (core/src/source.rs:343).

#### What is left
- A camera that sees the dice sees R; in dice-only mode R is the seed. Only "private setup" answers it.
- iPhone screenshots cannot be blocked, only answered by a discard; VoiceOver and TalkBack speak secrets (MA:17;
  todo:20293-20300). API 31-33 accessibility residual removed by minSdk 34 (todo:18128).
- Real-device capture checks are owed: I0-I5 (iPhone), Pixel and Samsung before release (todo:20886-20887).
- Phones have radios; the defense is airplane mode plus Wi-Fi off and a wipe on going online (MA:125).

#### Findings
- None.

### 4. Sensor manipulator (DS:63)

Defense promised: never trust one environmental source; credit sensors near zero.

#### What answers it
- Extras are a separate type that no credit path reads (`ExtraSource`, core/src/source.rs:43-55); `quota_met`
  sums only `CreditedSamples` and the OS policy credit (core/src/source.rs:113-117).
- Extras are absorbed only in Mixed mode, only while `Collecting` (core/src/session/inner.rs:128-137;
  ffi/src/ceremony.rs:929-935); a pool fault from an extra is kept and fails `commit` (inner.rs:165-167).
- Phones pass only touch timing and motion (ffi/src/wire.rs:663-669); the Pi passes key timestamps
  (pi/app/src/extras.rs:37; pi/app/src/app.rs:594).
- hwrng: SP 800-90B RCT cutoff 6, APT window 512 cutoff 62, 1,024 startup samples discarded, failures latch
  (core/src/health.rs:26-34, :90-135); boot test before Home (pi/app/src/app.rs:548-554).

#### Tests that prove it
- `the_pi_quota_needs_a_whole_window_of_hwrng` adds a MiB of each extra and still gets 0 credit and `QuotaUnmet`
  (core/tests/error_injection.rs:394, :424-440).
- Health: `every_keepcrypt_json_case_in_any_chunking`, `startup_samples_are_reported_for_discarding`,
  `credit_arrives_per_completed_window`, `a_failed_tester_stays_failed_and_credits_nothing`
  (core/src/health.rs:261, :298, :315, :337); `every_health_case_through_the_session` (core/tests/error_injection.rs:346).
- Extras reach D: `a_changed_source_id_or_a_dropped_extra_changes_d` (core/tests/source_substitution.rs:281).

#### What is left
- The hwrng itself is the one credited physical source on the Pi; an EM or temperature attack that biases it
  below H = 4 but above the APT/RCT cutoffs is not detectable by these tests (DS:89 calls the block closed).
- "Raw" hwrng samples are whatever the closed BCM2835 block outputs; whether it conditions internally is
  unknown (auditor question).
- Phase-2 extras (camera, microphone) and the M8 gate "tests prove extras can never satisfy a quota" (BP:301)
  are future; today's proof is the test above.

#### Findings
- None.

### 5. Forensic examiner (DS:64)

Defense promised: read-only OS, no swap, RAM-only secrets, zeroize after use.

#### What answers it
- Pi OS: SquashFS root mounted `ro`, `init_on_free=1`, no `console=` (pi/os/board/pizero/cmdline.txt:1);
  `/tmp` and `/run` tmpfs (pi/os/board/pizero/rootfs-overlay/etc/fstab:5-8); `CONFIG_SWAP`, `CONFIG_ZSWAP`,
  `CONFIG_ZRAM`, `CONFIG_COREDUMP`, `CONFIG_DEBUG_FS` forbidden (pi/os/expected/kconfig-forbidden:5-9);
  `CONFIG_INIT_ON_FREE_DEFAULT_ON` required (kconfig-required:25).
- Pi process: silent panic hook (pi/app/src/device/linux.rs:59), `mlockall` or stop (:75-78).
- Core: one `Box<Inner>` zeroized on every exit (core/src/session.rs:5-8); secret wrappers with no
  `Debug/Display/Clone` (core/src/secret.rs); R zeroized after E (core/src/session/inner.rs:228); pool digest
  zeroized (core/src/pool.rs:57); health tester `ZeroizeOnDrop` (core/src/health.rs:53-71).
- Only file written: the age backup (rule 8); FFI's panic hook silent (ffi/guard/src/lib.rs:31).

#### Tests that prove it
- `zeroize_clears_every_field` (core/src/session/inner.rs:517), `every_wrapper_zeroizes_every_field`
  (core/src/secret.rs:472), panic paths `a_panic_while_collecting_wipes_the_session` and siblings
  (core/tests/panic_wipe.rs:41-100), `no_seed_word_is_printed` (core/tests/no_secret_text.rs:510), the
  `*_not_debug_display_clone.rs` compile-fail fixtures.
- Image config: `banned-api-check.sh --os-config pi/os` (entropy-ci.yml:366) and `--image` (entropy-pi-image.yml:215-223).
- Android crash path: `anUncaughtExceptionWipesAndEndsTheProcessSilently`
  (mobile/android/app/src/androidTest/kotlin/com/keepcrypt/entropy/CrashTest.kt:36).

#### What is left
- Library copies core cannot wipe (todo:1407-1420), qrcodegen's freed `Vec<bool>` (todo:732) and
  qrcodegen-no-heap's stack temporaries (todo:6782).
- Phones: JVM strings and caches, tombstones, vendor swap, crash buffer, Swift strings and SwiftUI text
  (MA:17; todo:1522-1531, :1800, :14109-14111).
- A kernel panic hangs (`panic=0`) with the panel showing its last frame, possibly words (todo:1016-1017).
- RAM contents after power-off (remanence) are not addressed anywhere in docs or todo.md (to check).
- The crash path on real Pi hardware moves to M8's bench image (todo:1172).

#### Findings
- (new, low) The boot screen's integrity prefix covers partition 2 only. The image's FAT partition 1 holds
  `zImage`, the DTB, `cmdline.txt` and `config.txt` (pi/os/board/pizero/genimage.cfg:5-17), but the prefix
  hashes only the SquashFS on `/dev/mmcblk0p2` (pi/app/src/device/rootfs.rs:4-5, :52-72). A changed kernel or
  `cmdline.txt` (dropping `ro` or `init_on_free=1`) leaves the prefix the user compares with CI's unchanged.
  DS:123 asks for "a verified image"; PF:58 is accurate ("its own root filesystem") but does not say the boot
  partition is outside it. Suggest: say so in PF:58 and the audit packet, or hash partition 1 too.

### Core principles (DS:74-82)

#### P1 Entropy belongs to the process, not the output
- Answers: raw hwrng samples are health-tested before any hashing and only then absorbed
  (core/src/session/inner.rs:115-124; core/src/health.rs:90-108).
- Tests: core/src/health.rs:261, :298; core/tests/error_injection.rs:346.
- Left: no lab measurement of the raw source yet (DS:165-167, :283; M8). Whether `/dev/hwrng` output is
  physically raw is unknown (closed block).
- Findings: the known DS:167 item above.

#### P2 Credit min-entropy conservatively
- Answers: hwrng 4 bits/byte (core/src/source.rs:31), credit only per completed window (core/src/health.rs:36-48);
  extras 0 (core/src/source.rs:113-117).
- Tests: core/src/source.rs:251; core/tests/error_injection.rs:394.
- Left: the 4 bits/byte is policy, not measurement; the phone's 256-bit OS credit is policy (DS:190).

#### P3 Never narrow the pipe
- Answers: 512-bit pool, 256-bit D, E, S (core/src/pool.rs:26-58; core/src/seed.rs:76); no `as` casts in core
  sources (grep of core/src: none outside comments); `u64::try_from` for lengths (core/src/pool.rs:43-44).
- Tests: core/src/pool.rs:149; core/src/seed.rs:666, :692; birthday job and canary (entropy-nightly.yml:46, :72).
- Left: birthday coverage gaps listed under threat 1.

#### P4 Only cryptographic primitives
- Answers: SHA-512/256 from `sha2`; banned RNG crates (deny.toml:58-65); grep gate and artifact symbol scan
  (scripts/banned-api-check.sh:108-128); `StdRandom` rule against `RandomState` in linked files (:118-125).
- Tests: `banned-api-check.sh --selftest` (entropy-ci.yml:397-401), `scripts/canaries.sh` (entropy-ci.yml:321).
- Left: grep blind spots recorded as residuals (todo:2142-2155): discard shapes, obfuscated paths,
  `RandomState` used as a PRNG in pi/app, code under `cfg(not(debug_assertions))`.

#### P5 Hash-concatenate, never XOR
- Answers: core/src/pool.rs:38-49 (id || len || data). No XOR of secret material in core sources (only test
  bit-flips and CRC-32 in core/src/ur.rs:112-130).
- Tests: `split-ab-c` vs `split-a-bc` (core/src/pool.rs:120-124); core/tests/source_substitution.rs:281.

#### P6 Fail closed
- Answers: core/clippy.toml:11-32; core/Cargo.toml:116-128; latching health tester (core/src/health.rs:90-99);
  hwrng 2 s deadline then halt (pi/app/src/device/hwrng.rs:25, :48-73); Pi halts on any start-up fault
  (pi/app/src/device/linux.rs:59-90).
- Tests: `the_os_source_failing_halts_and_wipes`, `short_reads_halt_and_wipe`,
  `every_os_read_of_a_ceremony_halts_and_wipes`, `every_kat_at_new_and_at_restart`,
  `every_kat_through_each_free_function` (core/tests/error_injection.rs:126, :186, :293, :585, :667);
  `every_os_error_is_a_source_fault` (core/src/source/os.rs:30).
- Left: a read blocked inside the kernel on the hwrng `reading_mutex` is not bounded by the 2 s deadline
  (pi/app/src/device/hwrng.rs:12-15; todo:8101-8103); phone fail-closed windows (M5-54, todo:15739-15752).

#### P7 Test the path, not the presence
- Answers: source substitution (core/tests/source_substitution.rs:151-281); the artifact scan requires the OS
